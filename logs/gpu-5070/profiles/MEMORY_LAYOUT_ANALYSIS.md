### 5. Device-to-Host (D2H) 传输

#### 5.1 D2H 传输统计方法

**统计依据**: 通过分析日志文件中的内存追踪标记

1. **识别 D2H 传输事件**:
   ```bash
   grep "\[Memory\] Before CopyFromDevice (D2H): poly size=8388608" log_file
   ```
   - 日志中每次 D2H 传输前都会记录 `[Memory] Before CopyFromDevice (D2H)` 标记
   - Outer Circuit 中多项式大小为 8,388,608 coefficients（256 MiB）

2. **统计 batchApply 调用**:
   ```bash
   grep "Processing.*polynomials in batchApply" log_file
   ```
   - 每次 `batchApply` 调用会处理多个多项式
   - 每次处理 14 个多项式（共 15 个，跳过 id_ZS）

3. **计算总传输量**:
   - 传输次数 = 日志中 D2H 标记的数量
   - 每次传输大小 = 256 MiB
   - 总传输量 = 传输次数 × 256 MiB

#### 5.2 D2H 传输统计结果

**统计结果**:
- **D2H 传输次数**: 56 次（通过统计日志中的 D2H 标记得出）
- **每次传输大小**: 8,388,608 coefficients × 32 bytes = 268,435,456 bytes (256.00 MiB)
- **总 D2H 传输量**: 56 × 256 MiB = 14,336 MiB ≈ **14 GB**

**传输模式分析**:
- **batchApply 调用次数**: 4 次（在 `computeNumerator` 中，每次耗时约 5 秒）
- **每次 batchApply 中的 D2H 传输**: 14 次（每个多项式一次）
- **传输分布**: 4 次 batchApply × 14 个多项式 = 56 次 D2H 传输

**传输前后内存**: GPU 内存保持 7510 MiB（不变）

**观察**: 
- D2H 传输发生在 `toCosetLagrange` 处理过程中
- 每次传输 256 MiB，但 GPU 内存不减少（因为数据仍在 GPU 上用于后续处理）
- 传输主要用于将结果回传到 CPU 进行后续计算

**性能影响**: D2H 传输是性能瓶颈之一，每次传输约 160-200 ms，总传输时间约 9-11 秒。

- 14 个多项式释放后，GPU 内存从 7510 MiB 降至 3926 MiB

- 说明内存释放是完整的，没有内存泄漏

#### 释放顺序
- 释放顺序与上传顺序一致
- 内存释放是线性的，每个多项式释放 256 MiB

### 3. 内存复用

#### SRS 和 Tables
- SRS 和 Tables 在整个证明过程中保持驻留
- 这些数据在多个 coset 处理中复用
- 内存使用稳定在 3926 MiB

#### 多项式缓冲区
- 多项式缓冲区在每个 coset 处理完后释放
- 下一个 coset 处理时重新分配
- 这是内存使用的主要波动来源

### 4. D2H 传输模式

#### 传输频率
- 每个多项式在 `toCosetLagrange` 处理时都会执行 D2H 传输
- 6 次 batchApply，每次处理 14 个多项式
- 总共 84 次 D2H 传输

#### 传输开销
- 每次传输 256 MiB，耗时约 160-200 ms
- 总传输量 21 GB，是性能瓶颈之一

## 💡 优化建议

### 1. 内存池化
**问题**: 每个 coset 处理时都要重新分配和释放多项式缓冲区  
**建议**: 使用内存池复用缓冲区，减少分配/释放开销

### 2. 延迟释放
**问题**: 多项式在处理完后立即释放  
**建议**: 延迟释放，在确认不再需要后再释放，减少内存碎片

### 3. 减少 D2H 传输
**问题**: 每个多项式处理时都要执行 D2H 传输，总传输量 21 GB  
**建议**: 
- 只在必要时执行 D2H 传输
- 批量处理多个多项式后再统一传输
- 考虑在 GPU 上完成更多计算，减少 CPU-GPU 数据传输

### 4. 批量上传
**问题**: 14 个多项式逐个上传  
**建议**: 如果可能，批量上传多个多项式，减少 H2D 传输次数

### 5. 内存预分配
**问题**: 内存分配在运行时进行  
**建议**: 在初始化时预分配所有需要的缓冲区
